# Course Board UI デザインルール

UI 改善（多言語化・平易化・詰め込み解消）の作業で決まったルール集。
新しい画面や文言を追加するときは、まずここに従う。

## 1. 表示言語

3ロケール。`ja` が原文で、他は `ja` へフォールバックする。

| コード | 表示名 | 役割 |
|---|---|---|
| `ja` | 日本語 | 原文。すべてのキーはまずここに定義する |
| `ja-plain` | わかりやすい日本語 | IT・業界用語に不慣れな**大人**向けの言い換え |
| `en` | English | 英訳 |

切り替えは アカウントメニュー / ⌘K / 設定 から。選択は `localStorage`（`courseboard.locale`）に保存。

### わかりやすい日本語（ja-plain）の書き方

対象は「ITに詳しくない大人のスタッフ」。**日本語学習者や子ども向けの「やさしい日本語」ではない**。

- 漢字は普通に使う。ひらがな化・分かち書きは**しない**（かえって読みにくくなる）
- 変えるのは語彙・文の長さ・具体性:
  - カタカナIT用語・業務ジャーゴンを日常語に言い換える
    - タイムライン → 今日の予定表 / 配置 → 今日の担当決め / 月次精算 → 1か月のしめ
    - インポート → 読み込む / ステータス → 今の状態 / スタッフ紐づけ → 社員情報と結びつける
  - 一文を短く。操作は「何をどこで押すか」まで具体的に書く
  - 略語・英字は初出で補足する（CSV → 表のファイル（CSV））
- `ja` と同じ表現になるキー（「閉じる」等）は定義せず、フォールバックに任せる
- ただし**説明文（description / summary / message / body で終わるキー）は必ず書き直す**。
  `src/i18n/completeness.test.ts` が検証している

### i18n 実装の約束

- ライブラリは i18next + react-i18next。初期化は `src/i18n/index.ts`（`main.tsx` で side-effect import）
- 文言は `src/i18n/locales/<locale>/<namespace>.ts` に、画面単位の namespace で置く
- `en` / `ja-plain` は `DeepPartial<typeof ja側>` で型付けし、欠けは tsc でなくテストで検出する
- namespace を増減したら `node scripts/gen-i18n-index.mjs` で各 index.ts を再生成する
- ロケールコードに大文字を含めない。i18next の正規化（`ja-EASY` 化）を避けるため
  `lowerCaseLng: true` を維持する
- コンポーネント外（バリデーション関数・エラーマップ等）は `i18next.t()`、
  コンポーネント内は `useTranslation()` を使う。言語切替に追従させるため、
  モジュール読み込み時に `t()` の結果を定数に固定しない
- API が返すコード値（`primary` / `junior` 等）は**そのまま表示しない**。
  ラベル関数で翻訳キーへマップし、未知の値のみ原文表示にフォールバックする
- デプロイ担当者しか読まない設定エラー（env 不備など）は翻訳しない

## 2. 画面構成

- **1画面1目的。** 一覧と詳細を同じ画面に横並びで押し込まない。
  一覧はテーブル、行クリックで全幅の詳細へ遷移し、「← 戻る」で一覧へ戻す
  （例: キャディ名簿 `golf/caddies` ⇄ `golf/caddies/{id}`）
- 一覧に着地したら**まず一覧を見せる**。先頭行を自動選択して詳細を開かない
- 見出しを重複させない。詳細画面では PageHeader を出さず、対象の名前を見出しにする。
  パネルのタイトルがページ見出しの繰り返しになるなら省く
- 毎日使う画面だけをサイドバーに置く。使用頻度の低い画面（コース設定・予約ルール・
  コースマップ）は設定ハブ配下に寄せ、⌘K からは引き続き検索できるようにする
- **設定ハブには「決めること」だけを置く。** 動作状態・連携用JSONなどの技術詳細は
  下位ページ（`settings/advanced` = システム連携の詳細）へ移す。ハブは
  リンク一覧＋日常的に触りうる設定だけにする
- **追加・編集フォームを一覧の途中に差し込まない。** 右からの Sheet
  （`src/components/Sheet.tsx`）か別ページにする。一覧の上にフォームが展開すると
  表が押し下げられ、文脈が切れる（例: プレー商品のプラン追加は Sheet）
- 1画面あたりの指標（Metric）・見出しは絞る。詰め込むより分割する
- **一覧の件数を言い換えただけの指標カードは置かない**（「登録したプラン 2」等は
  表を見れば分かる）。指標は計算した結果（達成率、受けられる残り組数など）に限る

## 3. 文言（ja 原文も含む）

- 原文の `ja` 自体も業務語で書く。内部実装の名前（Field API、extension runtime、
  テナントマスタ等）を UI に出さない
- エラーは「何が起きたか＋次に何をすればよいか」を書く。内部サービス名で説明しない
- ヘルプパネルは 1見出し2〜3文まで。「この画面ですること」と「出てくることば」の2部構成

## 4. コンポーネントの細部

- ドロップダウン内でチェックマーク付きの選択肢を並べるときは、未選択行に
  同じ幅のスペーサー（`.menu-check-spacer`、0.875rem = アイコンと同幅）を置き、
  ラベルの左端を揃える。スペーサーには `aria-hidden="true"`
- レイアウト方式（flex ⇄ grid）を変えたら、**メディアクエリ内の旧ルールまで**掃除する。
  `.metric` の `max-width: 50%` が grid セルに残って崩れた前例あり
- 疑わしいレイアウトは推測せず、ブラウザで computed style を実測して原因を特定する

## 5. 検証

- 文言変更を含む PR は `npx vitest run` を通す。
  - `src/i18n/completeness.test.ts`: en の全キー網羅 / ja にないキーの検出 /
    プレースホルダ一致 / ja-plain の説明文書き直し
- テストは `ja` 固定で走る（`src/test/setup.ts`）。文言をアサートするテストは ja の文言で書く
- UI 変更はブラウザ（`preview_start` / `npm run dev`）で3ロケールとも目視確認する
