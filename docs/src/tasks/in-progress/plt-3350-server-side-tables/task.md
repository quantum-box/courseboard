# PLT-3350 一覧の検索・ソート・ページングをサーバー側へ寄せる

## 問題

共有 `DataTable`（`desktop/src/components/Page.tsx`）は、受け取った全行をブラウザで検索・並べ替え・ページ分割する。行数に上限がある一覧（キャディ名簿、1日の配置、月次給与）はこれで足りるが、件数が際限なく増える一覧では「サーバーから取る件数の上限」が実質の天井になり、上限を超えた行は画面から見えなくなっていた。

## 一覧ごとの判断

| 一覧 | データ源 | 件数の性質 | 対応 |
|---|---|---|---|
| 架電リスト | CourseBoard `golf_customer_summaries` | 顧客台帳の人数に比例（数千〜） | **サーバー側**（本 PR）。100 件で打ち切っていた |
| キャンセル一覧 | CourseBoard `golf_reservation_cancellations` | 期間に比例 | **サーバー側**（本 PR）。100 件で打ち切っていた |

**切り替えの基準**: 件数が業務の累積（顧客・予約・請求）に比例して増える一覧はサーバー側。人員やマスタのように組織の規模で頭打ちになる一覧はクライアント側。

## 規約

- ページングは offset 方式（`limit` / `offset`、応答に `total`）。Field の大半の一覧と同じ形に揃える。
- 並べ替えは `sort`（閉じた列挙）と `ascending`（既定は降順）。SQL の列は列挙から引き、リクエストを文に埋め込まない。
- 値の無い行は昇順・降順どちらでも末尾（`col IS NULL, col` の順）。クライアント側 `sortRows` と同じ規則。
- 並べ替えの同値は一意な列で崩し、ページをまたいで行が入れ替わらないようにする。
- Field から 1 ページ分だけ引く列（氏名・電話番号）はサーバー側で並べられないので、並べ替え可能にしない。

## UI

`DataTable` に `server` を渡すと制御モードになる。`rows` は現在のページ、`page` / `total` / `sort` は呼び出し側が持ち、`onPageChange` / `onSortChange` で要求だけを返す。列は `sortValue` の代わりに `serverSortable` で並べ替え可能を宣言する。次のページを読む間は `useKeptData` で前のページを薄く表示し、ページャが消えないようにする。
