# 日別予約状況の取り込み（撤去済み）

Linear: PLT-3247（仕様確定）/ PLT-3248（取り込み）/ PLT-3249（冪等性）/ PLT-3250（プレビューとエラー表示）

## この作業は取り下げた

同じ帳票を取り込む実装が2つ並行して作られ、両方が main に入った。

- この taskdoc の実装（#198、#222）— CourseBoard の DB に `golf_reservation_day_summaries`
  と `golf_reservation_course_links` を作り、xlsx を CourseBoard 側の calamine で解析した。
- [reservation-report-import](../../completed/v0.1.11/../v0.1.10/reservation-report-import/task.md)（#212）—
  Field の汎用 tabular analyze に CSV / Excel / PDF を解析させ、集計を Field の
  extension config に置いた。

**残したのは後者。** [ADR-0007](../../../architecture/decisions/ADR-0007-external-reservation-report-snapshots.md)
が保存先を決めており、その Alternatives Considered は前者の形（CourseBoard に専用テーブル）を
「ADR-0005 の物理移送禁止に反する」として明示的に不採用にしている。

前者の撤去が `202608140001_drop_golf_reservation_summary_tables.sql`。

## 残したほうが優れていた点

判断の材料として、比較で分かったことを残す。

- **付け替え・除外時の古い行**: #212 は行を `sourceCourseKey`（帳票上の施設名）で引き、
  有効な全コースを走査して掃除する。こちらは同じ結論に辿り着くまでに数回の修正を要した。
- **複数の施設名が1コースに対応**: #212 は対応付けの検証で reject する。こちらは合算して
  警告を出す形にしたが、reject のほうが単純で、silent な取りこぼしも起きない。

移植すべきものは無かった。

## 未検証のまま残した確認

実ファイル（`日別予約状況_組数_20260718_202607_真駒内_滝の_羊ケ丘.xlsx`）を #212 の経路で
読ませた検証は**行っていない**。#212 は Field の tabular analyze を経由するため、Field への
到達手段が要る。こちらの実装で実物から確定させた値を、突き合わせの基準として残す。

- 真駒内 7/1 午前 = 組数 56 / キャディ付き 21
- 真駒内の 7/6・7/7・7/9〜7/12 は**休場で 0**。データ欠損ではない
- `全体` 行と個別施設の和が一致する
- 日付セルには天気が同居する。コース名セルは結合されている。予算行には全角ハイフン `－` が入る
- ファイル内に年が無いので、年は外から与える必要がある

## 元の前提（記録として）

札幌カントリー倶楽部の予約は ICグリーンシステムにある。そこから出せるのは日次サマリの
ファイル1つだけで、予約明細は出せない（2026-08-09 先方確認済み）。スタート時刻も、
予約1件ごとのキャディ有無も出ない。したがって Field の予約在庫には落とせない —
枠に紐づく事実が1つも無く、枠を消費させようとすると存在しない明細を捏造することになる。

この前提自体は ADR-0007 でも変わっていない。変わったのは「ではどこに置くか」の答えで、
CourseBoard の DB ではなく Field の運用スナップショットになった。
