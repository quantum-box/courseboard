# 日別予約状況の取り込み

Linear: PLT-3247（仕様確定）/ PLT-3248（取り込み）/ PLT-3249（冪等性）/ PLT-3250（プレビューとエラー表示）

## 前提

札幌カントリー倶楽部の予約は ICグリーンシステムにある。**そこから出せるのは日次サマリのファイル1つだけで、予約明細は出せない**（2026-08-09 先方確認済み）。

- **スタート時刻は出ない**
- **予約1件ごとのキャディ有無は出ない**（出るのは日×時間帯で集計したキャディ付き組数のみ）

したがって取り込んだデータを Field の予約在庫（`reservation_time_slots`）に落とすことはできない。枠に紐づく事実が1つも無いので、枠を消費させようとすると存在しない明細を捏造することになる。**在庫とは別系統として、CourseBoard 自身の DB に持つ**（ADR-0005。`golf_slot_overrides` / `golf_caddie_shifts` と同じ理由・同じ流儀）。

保持できる粒度は **日 × コース × 午前/午後 → 総組数 / キャディ付き組数** の一択。

## 入力ファイル

`日別予約状況_組数_20260718_202607_真駒内_滝の_羊ケ丘.xlsx`
（2026-07-18 出力 / 2026年7月分。**CSVではなく xlsx**。シート1枚 `日別予約状況`、70行 × 67列）

テストフィクスチャに実物を入れてある: `tests/fixtures/日別予約状況_組数_20260718_202607_真駒内_滝の_羊ケ丘.xlsx`

### 行 = コース × 系列 × 時間帯

| 軸 | 値 |
|---|---|
| コース（A列） | 全体(81H) / 真駒内(36H) / 滝の(27H) / 羊ケ丘(18H) |
| 系列（B列） | 本年 / 前年実績 / 前年同日 / 予算 / 差異(本年-前年実績) / 差異(本年-前年同日) / 差異(本年-予算) |
| 時間帯（C列） | 午前 / 午後 / 合計 |

A列・B列はセル結合で縦に伸びており、ブロックの先頭行にしか値が入らない。

### 列 = 合計 + 7/1〜7/31 の各日

1日あたり2列（`組数` と `ｷｬ付`）。ヘッダーは2段（1行目 = 日付＋天気の結合セル、2行目 = `組数` / `ｷｬ付`）。

### 取り込む範囲

**`本年` 行 × コース別（真駒内 / 滝の / 羊ケ丘）× 午前・午後 の `組数` と `ｷｬ付` だけ。**

除外するもの:

- `全体` 行 … 3コースの合計。取り込むと club を二重に数える。**検算にだけ使う**
- `合計` 行 … 午前＋午後。取り込むと月を1.5倍に数える
- `合計` 列 … 月の累計。取り込むと31日分の日が1つ増える
- `前年実績` / `前年同日` / `予算` / `差異` 行 … 予約の事実ではなく比較用の数字

## パース仕様

実装は `src/course/domain/reservation_sheet.rs`（意味づけ）と `src/course/infrastructure/reservation_workbook.rs`（xlsx読み）に分かれている。**ファイル形式の知識は infrastructure だけが持ち、レイアウトの解釈は domain が持つ。** 難しいのは後者なので、スプレッドシート無しでテストできるようにしてある。

| 事情 | 扱い |
|---|---|
| 日付に年が無い（`7/1(水)`） | 年はファイル名の `202607` から補完する。`20260718` は出力日なので使わない（8月分を7月に出すと1か月ずれる） |
| 日付セルに天気が改行で同居（`7/1(水)\n晴→晴`） | 改行の前だけ使う。**天気は当てにしない**（このファイルは7/18(土)を「曇→曇り後雪」と書いている） |
| 12月ファイルに1月の列がある場合 | 月が戻ったら翌年として扱う |
| A列・B列がセル結合 | 直前の非空セルを持ち回る（人がページを読む読み方と同じ。結合をやめた出力にも耐える） |
| ラベル列の位置 | `ゴルフ場` / `項目` / `時間帯` の見出しから探す。位置決め打ちにすると上流の列追加で全数値が横にずれる |
| 予算行の `ｷｬ付` が `－`（全角ハイフン） | そもそも取り込まない行。数値化できないセルは `None` として扱う |
| 数値が `147.0` で来る | 整数として読む。`147.5` は組数ではないので読まない |
| 真駒内が 7/6, 7/7, 7/9〜7/12 で 0 | **休業。データ欠けではない。**（→下記） |

### 真駒内の 0 について（PLT-3247 の要確認事項）

PLT-3247 起票時の「7/9以降ずっと0」は**実ファイルと合っていない**。実際に 0 なのは **7/6・7/7・7/9・7/10・7/11・7/12 の6日だけ**で、7/13以降は 45〜77組で通常営業している。7/8 は午前40組・午後0組。同じ日に滝の・羊ケ丘は通常どおり動いており、`全体` 行もその6日を 0 込みで正しく合計している。

つまり**コース単位の休業日**であって、ファイルの欠損ではない。よって **0 は 0 として保存する**。行ごと落とすと、前回取り込みの数字が休業日に残り続ける。

## 保存

`golf_reservation_day_summaries`

```
UNIQUE (tenant_id, golf_course_id, summary_date, time_of_day)
```

`time_of_day` は `am` / `pm`。この一意キーがそのまま冪等キーになる（PLT-3249）。

取り込みは **upsert ではなく「窓の置き換え」**にしている。1トランザクションの中で

```
DELETE ... WHERE tenant AND summary_date BETWEEN ファイルの初日 AND 最終日
                AND golf_course_id IN (突き合わせできたコース)
INSERT ...
```

**入っている行だけ書くと、新しいファイルが報告しなくなった半日に前回の数字が残る。** 例えば前回は読めた 7/3 午前のセルが今回は読めない場合、警告は出るのに画面には前回の数字が出たままになり、どの日が新しいのか分からない board になる。窓ごと置き換えれば、ファイルがその窓の全てになる。

窓の範囲は**シートの日付列から取る**（残った行の min/max ではない）。両方の半日が読めなかった日も窓の内側に入れないと、その日だけ前回のまま取り残される。

削除の対象は**突き合わせできたコースだけ**。コース名の変更でマスタと合わなくなったコースは、警告は出すが既存データは消さない。リネームで1か月分の予約が消えるほうが害が大きい。

1ファイルは1トランザクション。半分だけ新しい月が残ると、画面上どの日が古いのか分からなくなる。

コース名の突き合わせは `match_course_label`。ファイルは `羊ケ丘`、マスタは `羊ヶ丘` のように小書き「ヶ」が揺れるので、正規化して比較する（`ヶ`/`ヵ` → `ケ`、空白除去、末尾の `36H` 除去）。完全一致 → 部分一致の順で、**候補が2つ以上あるコースは取り込まず警告する**。当てずっぽうで当てると、1か月分の予約が黙って別コースに乗る。

## 検算

取り込んだ3コースの合計を、ファイル自身の `全体` 行と突き合わせる。合わなければ警告を出す。上流のレイアウト変更でコースが1つ落ちたときの見え方が「月がなんとなく少ない」だけになるのを防ぐための、唯一の手がかりになる。

実ファイルでは全31日 × 午前午後の全てで一致する（`reservation_workbook.rs` のテスト）。

## 画面（PLT-3250）

`golf/reservation-import`。2段階にしてある。

1. **中身を確認する** … 何も書き込まない。件数・コースごとの内訳・警告・日ごとの組数を出す
2. **この内容で取り込む** / **やめる**

書き込まない確認段階があるので「やめる」が嘘にならない。

### 対象月の指定

ファイル名に `YYYYMM` が無いときは **400 `month_required`** を返し、そこで初めて画面が月の選択を出す。**画面側で勝手に補って再送しない。** 一覧のフィルタに出ている月をそのまま送ると、無関係な月に1か月分の予約が黙って入る。

選択が出るまで `yearMonth` は一切送らない。出たあとの選択は今月から始まる（年月の select に空の状態は無い）が、それでよい。エラー文が出ている状態で利用者がボタンを押し直す明示的な操作であって、黙って再送しているわけではない。

`month_required` は他の 400 と別のエラーコードにしてある。画面が「答えれば直る」ものと「そうでない」ものを区別する必要があり、英語の文面で判定するのは壊れやすい。

### エラー文

**行番号を出さない。**「8月3日の予約が読めません」のように、その人が確認しに行ける単位で書く。警告はサーバから構造化して返し（`kind` + 日付・コース名）、文言は画面側の i18n が持つ。

`unknownCourse` / `ambiguousCourse` はコース丸ごと落ちる（＝月の1/3が入らない）ので danger、それ以外は warning。

ファイル自体が読めない・`本年` 行が1つも無い・どのコースもマスタに無い、といった**利用者が直せる**入力の問題は 400 で返す。上流障害（424 `provider_error`）と混ぜない（PLT-3185 の指摘）。

## この作業に入っていないもの

- **必要キャディ数の算出と割当への接続**（PLT-3339）。取り込みは配置に一切触らないので、再取り込みで既存の割当が消えることはない。「必要数が減った日だけ、はみ出した割当を外す」（PLT-3249 の Done 4つめ）は割当側の判断なので PLT-3339 に属する
- 予約在庫（`reservation_time_slots`）との連動。前提のとおり不可能
