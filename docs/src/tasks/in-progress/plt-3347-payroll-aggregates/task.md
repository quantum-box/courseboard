# 給与の集計値（月合計・ランク別内訳）の置き場所

## Links

- [PLT-3347](https://linear.app/issue/PLT-3347)
- 集計を画面から外した PR: [courseboard#183](https://github.com/quantum-box/courseboard/pull/183)
- 月次精算を CourseBoard で計算する PR: [courseboard#284](https://github.com/quantum-box/courseboard/pull/284)
- [ADR-0005](../../../architecture/decisions/ADR-0005-golf-domain-ownership.md) / [ADR-0009](../../../architecture/decisions/ADR-0009-extension-config-is-not-a-data-store.md)

## 背景

#183 で給与画面を「1か月ぶんを1行ずつ突き合わせる」一覧に絞り、次の数字を画面から外した。

- 支給額の合計 / 担当したラウンド / 確認が必要
- ランク別の内訳（人数・ラウンド数・金額）

以後、これらはどの画面にも出ていない（CSV には行単位で全項目が残っている）。
集計関数 `payrollTotals` / `rankTotals`（`desktop/src/features/golf/caddieRankFees.ts`）は
テスト付きで残っていたが、呼び出し元が無かった。

## 決定

### 1. データの置き場所: どこにも保存しない。読むたびに CourseBoard で数える

- **Field には置かない。** ランクもランク別単価もキャディフィーの計算も、ADR-0005 で
  CourseBoard が所有するゴルフの語彙と計算。Field に起票する汎用 capability も無い。
- **CourseBoard ローカル DB にも snapshot を置かない。** 支給額は「その月のラウンド数 ×
  いまの単価」で毎回計算しなおす設計（#183）で、単価を直すと過去月も直る。月合計を保存すると
  単価修正のたびに古くなり、行の合計と保存値という 2 つの正ができる。
- 金額の算術（単価 × ラウンド）はサーバー（`src/course/domain/payroll.rs`）のまま。
  画面は `GET /v1/course/caddie-payroll-summary` の行を足し上げるだけ。API は無改修。

### 2. 画面: 分析ページは作らず、月次精算に寄せる

月次精算は「締める前に確かめる」画面で、会計が知りたいのは「この月キャディにいくら払うか」。
ランク別の内訳は、その合計がランク単価どおりに出ているかを確かめる材料なので、精算の側に置く。
給与画面（1 人ずつ確かめる）には戻さない。

月次精算に「キャディへの支給」パネルを足す。

- 支給額（いまの単価）/ 担当した人数・ラウンド数
- 割当時の額（既存の「キャディの費用」と同じ値）と支給額の差
- 確認が必要な人数（退勤なし・割当の日に出勤なし）
- ランク別の内訳（人数・うち本人ごとの単価の人数・ラウンド・支給額）
- 「給与の一覧を開く」で同じ月の給与画面へ

### 3. 既存の「キャディの費用」との関係: 置き換えず、並べて差を出す

2 つは別の問いに答えている（#284）。

| | 何を足すか | 答える問い |
|---|---|---|
| 割当時の額（精算の `caddieFees`） | 割当を作ったときに押された `fee_amount`、`assigned` / `completed` | いくら約束済みか |
| 支給額（給与サマリ） | 名簿のキャディごとに、キャンセル以外のラウンド数 × いまの単価 | いくら払うべきか |

片方に寄せると、精算の compare（`COURSEBOARD_SETTLEMENT_SOURCE`）が壊れるか、単価修正が
締めに見えなくなる。そこで既存メトリクスのラベルを「キャディの費用（割当時）」に改め、
新パネルで両者と差額を並べる。差があるときは原因の候補（単価の修正、名簿から外れた
キャディの割当）と「払うのは支給額」を注意として出す。

### 4. 月をまたいだ比較: 今はやらない

- **ランクは現在値しか持っていない。** ランク変更の履歴が無いので、過去月の「ランク構成」は
  いまのランクで数えなおされ、昇格が起きるたびに過去の推移が書き換わる。
- **支給額も遡って再計算される。** 単価を直すと前月比が動き、「推移」として読めない。
- 前月比を出す前提は「ランク変更の履歴」を持つこと。これはゴルフ固有なので、必要になったら
  ADR-0009 に従い **CourseBoard ローカル DB** に持つ（Field には起票しない）。
  その時点で分析ページの新設を改めて判断する。

内訳のバッジに「いまのランクで集計」と明記し、過去月を開いたときの誤読を防ぐ。

## 権限

支給額は `field_extension_golf:ListPayroll`、精算は `ListSettlement` で別の権限。
精算のレスポンスに給与を混ぜず、パネルが給与サマリを別に取る。403 のときはパネルごと出さず、
それ以外の失敗はパネル内にエラーを出して精算の残りは使えるままにする。
