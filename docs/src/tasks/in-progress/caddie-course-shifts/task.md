# キャディの確定シフトとコース別配置

## 現状

キャディをどのコースに置くかという情報が、どこにも存在しない。

- 所属コース（`CaddieCourseMembership`、メイン1つとサブ複数）は登録・編集できるが、`list_caddie_memberships` と `replace_caddie_memberships` 以外から読まれない。推薦も自動配置も需給も、コースを一切見ずに全キャディを1プールとして扱う。
- 日別に持っているのは休み希望（Field の golf extension、`caddie-availabilities`）だけで、未提出は出勤とみなす。事前に組んだ出勤枠という概念がない。休み希望には配置コースを入れる欄もない。
- `compute_caddie_supply` はテナント全体の日単位で、コース別の内訳を持たない。しかもこの供給値は予約可否に効いておらず、`create_reservation` にキャディ枠のチェックはない。キャディ付き予約は供給と無関係に売れる。
- 未割当ラウンドの手動指名は `golfCourseId` なしで tee-sheet を引くため、全コースの組が1つのリストに混ざる。候補もコース能力を見ない。

キャディ1人が1日に持てるのは基本2ラウンドで、これは既存の `maxRoundsPerDay` と `canTwoRounds` が表している。メイン / サブはコースごとの枠数ではなく、**どのコースに入れるかという能力**である。したがって membership に数は持たせない。

コースのキャディ付き予約枠は、そのコースに配置されたキャディの枠数合計から決まる。だから先に決まるべきは予約ではなくシフトで、シフトは予約の有無にかかわらず事前に確定する。

## 置き場所

確定シフトは CourseBoard 自身の DB に持つ。「その日このキャディをどのコースに置く」はゴルフの配置判断であり、Field の汎用 HRM には意味を持たせられない（ADR-0005）。休み希望の締切（`golf_availability_deadlines`）と同じ理由・同じ流儀で、CourseBoard 側のテーブルにする。Field 側の変更は要らない。

## データ

`golf_caddie_shifts` — テナント × 日 × キャディで一意。

- 配置コースID。メイン所属から生成され、サブ所属のコースへ手で移せる。
- 枠数（1 or 2）。`canTwoRounds` かつ2ラウンド希望なら2、それ以外は1。
- 時間帯（終日 / 午前 / 午後）。休み希望の `morning_only` / `afternoon_only` から引き継ぐ。
- 由来（自動生成 / 手編集 / 固定）。再生成が何を残すかをこれで決める。
- 休み希望に反する編集をしたときの理由メモ、更新者、更新時刻。

## フェーズ

## 休日の入れ方

労基法35条の週1日の休日を、生成側で保証する。**連続6日を超えて出勤にしない**（週の起算日に依存しない、より厳しい読み方）。月をまたぐ連続は前月末の確定シフトから数える。

上限は法律が決めるが、休みを窓のどこに置くかは選べる。締切ぎりぎり（7日目）に固定すると全員が同じ日に休んでコースが空になるので、次の順で選ぶ。

1. 本人が休み希望を出している日（コースの負担がゼロ）
2. クラブが「休みにしたくない」と設定していない曜日
3. その日すでに休む人が最も少ない日（人数の最大化）
4. その中で最も遅い日（月の休み総数を増やさない）

## シフトのルール（テナント設定）

生成に埋まっていた定数はすべて `golf_shift_rules` のテナント設定にする。既定値は設定前の挙動と同じなので、触らなければ何も変わらない。

- **休みにしたくない曜日**（既定 土日）。**禁止ではなく優先度**で、連続日数の窓に他の選択肢が無ければ保護した曜日も休みに使う。
- **連続勤務の上限**（既定 6日）。労基法35条の上限なので6日を超える値は API が拒否する。短くするのは自由。
- **1日に受け持つ組数の上限**（既定 2組）。キャディ個人の `maxRoundsPerDay` とは別の、クラブ全体の天井。
- **月の最低休日数**（既定 0＝指定なし）。就業規則で「月8日」などと決まっている場合。連続日数ルールだけだと月4〜5日にしかならないので、足りない分を同じ選び方（保護曜日を避け、人数の少ない日へ）で足す。休み希望で休みの日も数に含める。
- **休み希望が未提出の日の扱い**（既定 出勤）。提出率の低いクラブは「休み」にできる。

固定した日は動かさない。固定のせいで7日以上連続になる場合は、上書きせず名前を挙げて返す。

### 1. 確定シフトの保存と生成

- マイグレーションとリポジトリ、`src/course/` の4層。
- 月単位の一括生成：休み希望あり→休み、未提出→出勤、午前/午後のみ→半日、2ラウンド希望かつ `canTwoRounds`→枠2。配置コースはメイン所属。
- メイン所属がないキャディは配置せず、警告として返す。生成しても休み希望そのものは書き換えない。
- 生成後の編集：出勤/休み、時間帯、枠数、配置コースを日ごとに変更できる。**移動先はサブ所属を持つコースに限る。**
- 固定フラグ。立っているセルは再生成で作り直さない。
- 休み希望が出ている日を出勤に変える編集は、理由メモを必須にして通す。
- シフト表にコース列を出し、セルから編集する。

### 2. コース別の過不足と移動

- `compute_caddie_supply` をコース別集計に拡張し、配置コースごとに供給枠・キャディ付き予約数・過不足を返す。
- 配車画面に日×コースの過不足ボードを置き、余っているコースから不足コースへその日だけ移す。移動は配置コースの変更そのものであり、固定セルは移動候補から外す。

### 3. 配車の連動

- 未割当ラウンド、`caddie-recommendations`、`auto_assign_caddies` に `golfCourseId` を通す。
- 候補はその日そのコースに配置されたキャディを優先し、サブ所属の応援可能なキャディはそれと分かる形で後ろに並べる。配置されていないコースのキャディは候補にしない。

### 4. 予約枠への接続

- コース別供給をキャディ付き商品の販売上限として予約時にガードする。予約フローに触るのはここだけなので、1〜3が動いてから着手する。
- **確定シフトが1件も無い日はガードしない。** 月を確定していないだけで全予約が弾かれる方が、防ごうとしているオーバーブッキングより悪い。同じ理由で、推薦・自動配置のコース絞り込みも未確定の日には効かせない。

## 完了条件

- 締切後に月の確定シフトを生成でき、生成結果に休み希望・半日・2ラウンド希望・メイン所属が反映される。
- メイン所属のないキャディは配置されず、警告に名前が出る。
- 確定シフトを日ごとに編集でき、サブ所属を持たないコースへは移せない。
- 固定したセルは再生成でも過不足の移動でも書き換わらない。
- 休み希望が出ている日を出勤に変えるとき、理由メモなしでは保存できない。
- コース別の供給・予約数・過不足が日単位で取得でき、配車画面から余剰コースのキャディを不足コースへ移せる。
- 未割当ラウンドの候補が、その日そのコースに配置されたキャディに絞られる。
