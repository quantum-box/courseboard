## 概要

予約をキャンセルすると台帳から消えるだけで、何も残らない。

1. **キャンセルしたことが分からない。** `is_tee_sheet_candidate` が cancelled を落とすので、
   翌朝の受付には空き枠が見えるだけ。組が入っていて流れたのか、最初から空きだったのかを
   区別できない。
2. **理由が残らない。** 受付が打った理由は Field へ転送しているが、Field に置き場がなく
   （PLT-3297）、到着した時点で捨てられている。台風と無断キャンセルが同じ「消えた予約」になる。
3. **キャンセル料が予約とつながっていない。** キャンセル料は Field の請求書として作るが、
   作成画面は顧客ID・氏名・メール・金額・理由をすべて手入力。どのキャンセルに対する
   請求なのかはどこにも残らず、誰に請求済みで誰が未処理かも分からない。

理由の分類（天候・体調・自己都合・無断・コース都合…）は「キャンセル料を取るかどうか」を
決めるためのもので、これはゴルフ場の業務ルール。Field の汎用モデルに入れるものではないので
CourseBoard ローカル DB が持つ（ADR-0009）。Field への理由の転送は今まで通り続ける。

## Scope

### A. キャンセルの記録

- `golf_reservation_cancellations`: tenant / 予約 / 予約番号 / customer_id（任意）/ 予約時の氏名 /
  コース / ティータイム / プレー日 / 人数 / 予約金額 / 理由コード / 理由メモ / 何日前 /
  キャンセル料の状態 / 請求書ID / 金額 / メモ / 実施日時 / 実施者。
- 予約は Field から**キャンセルする前に**読む。キャンセル後は金額もティータイムも
  どの盤面にも残らないため。読めなくてもキャンセルは通す（受付は電話中）。
- 一意キーは (tenant, 予約)。2度目のキャンセルは理由を上書きするが、
  **すでに付いたキャンセル料の状態は触らない**。
- 理由コードは 8 種（`weather` / `illness` / `personal` / `no_contact` / `course_side` /
  `shortage` / `mistake` / `other`）。`fee_expected()` はコードから導出し、保存しない。
  club がルールを変えても backfill が要らない。
- プレー日はテナントのタイムゾーンで解決する。JST の朝の組は UTC では前日。

### B. 抽出と一括徴収

- `GET /v1/course/reservation-cancellations`: 期間（プレー日）・理由・状態・顧客・
  「キャンセル料の対象だけ」で絞る。氏名と連絡先は Field から**表示する行の分だけ**引く
  （架電リストと同じ。台帳のコピーは持たない）。
- `POST /v1/course/reservation-cancellations/fees`: 請求済み／免除をまとめて記録する。
  **請求書は先に Field 側で作り、実在するものだけを `invoiced` として書く。**
  実体のない請求書IDを指す行は次の抽出に二度と出てこないが、未処理の行は出てくる。
- 認可は読みが `ListCustomers`、徴収の記録が `ManageCancellationFees`（どちらも既存）。

### C. 画面

- 予約台帳のキャンセルダイアログ: 理由の区分（プルダウン）＋自由記述。既定は `personal`。
  `weather` を既定にすると、ふつうのキャンセルが全部「天災」で記録される。
- 予約台帳: 盤面の下に「この日のキャンセル」。枠には戻さない（枠は本当に空いている）。
- 顧客台帳 → 「キャンセルした人をさがす」: 期間・理由・状態で抽出し、複数選択して
  キャンセル料を一括請求 or まとめて免除。請求は**人ごとに1通**にまとめる。
- 顧客カルテ: キャンセルの履歴（理由つき）と、請求済みなら請求書へのリンク。
- キャンセル料の新規作成: 顧客IDの手入力をやめて `CustomerPicker` から選ぶ。

## Out of scope

- 何日前なら何割、という料金表そのもの。いまは1名あたりの金額を都度入力する。
- 支払い状態の複製。払われたかは請求書（Field）が正で、こちらには持たない。
- Field 側でキャンセル理由を持つ話（PLT-3297）。持てるようになっても、
  分類とキャンセル料の判断は CourseBoard に残る。
- Field 側の実装そのもの（PLT-3297 / PLT-4050 / 請求書の由来）。CourseBoard から
  書かず、業種非依存の contract として起票して待つ（CLAUDE.md）。
