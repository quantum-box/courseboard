# ページ遷移で前回表示をすぐ復元する

## Links

- [設計](./design.md)
- Linear issue: 未作成

## 概要

コース一覧、コース設定、プレー商品、予約台帳、予定表、キャディ名簿、シフト表、給与は遷移のたびにコンポーネントが再生成され、API応答を待つ間、前回
表示できていた内容までローディング表示へ置き換わる。一部画面では `useResource` のメモリ
キャッシュを利用しているため、同じ方式を代表導線へ適用する。成功した直近データを即表示し、
同時に裏で再取得する。

## Scope

- 読み取りAPIの成功結果をブラウザ内メモリへ保持し、再訪時に即表示する。
- キャッシュ表示後も再取得し、成功時に最新データへ置き換える。
- テナント切替、ログアウト、権限拒否ではキャッシュを全消去する。
- 作成、更新、削除後は関係するキャッシュを更新または再取得する。
- キャッシュが無い初回だけ全面ローディングを表示する。
- 最初の適用先はコース一覧、コース設定、プレー商品、予約台帳、予定表、キャディ名簿、シフト表、給与とする。

## Non-goals

- `localStorage` やIndexedDBへの永続化、オフライン対応。
- 認証プロフィール、決済秘密情報、入力途中のフォーム値のキャッシュ。
- APIやDB契約の変更。
- 予算、精算など、対象外画面への一括展開。

## 完了条件

- 一度表示した画面へ戻ると、通信完了前から前回データが見える。
- 再取得は省略せず、最新結果または再取得失敗を画面へ反映する。
- 別テナントのデータが一瞬でも表示されない。
- 変更操作後に古いキャッシュへ巻き戻らない。
- TypeScript、対象unit test、主要画面のPlaywright確認が成功する。

## リスクと保留

- メモリキャッシュのため、ブラウザ更新後は従来どおり初回読み込みになる。
- 一時的に古い内容を表示するため、更新日時や再取得失敗を隠さない既存表示を維持する。
- 編集可能な画面は未保存draftを再取得結果で上書きしない制御が必要なため、画面ごとに段階展開する。
- ライブ運用画面は再取得失敗時も直近表示を維持し、再試行可能なエラーを併記する。
- PR準備、version bump、commit、pushは本作業の範囲外。
