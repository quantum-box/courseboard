# 更新・再読み込みボタンを廃止する

## 概要

各画面に重複していた更新・再読み込みボタンを廃止し、画面の再取得は
`Cmd+R` / `Ctrl+R` から実行する。通常画面の操作対象を保存・追加・編集などの業務操作に絞り、
画面ごとの更新導線とショートカット導線の二重化をなくした。

## 対象と非対象

- 対象: 一覧、詳細、設定、タイムライン、台帳、キャディ管理などの通常更新・再読み込みボタン。
- 非対象: 保存後の内部再取得、エラー時の「もう一度試す」、認証回復操作。
- API、DB、認証契約、データモデルは変更しない。

## 対応

1. `PageRefreshButton` と通常画面の更新／再読み込みボタンを削除した。
2. `AppShell` の `Cmd+R` / `Ctrl+R` を、現在画面が登録した再取得ハンドラへ直接接続した。
3. エラー回復ボタンは通常更新操作と区別するため、更新アイコンとショートカット表示を外した。
4. `desktop/DESIGN.md` とショートカットテストを更新した。

## 検証

- `cd desktop && npm run type-check`
- `cd desktop && npm run test`（42 files / 391 tests）
- `cd desktop && npm run build`
- 開発用環境を別ポートで起動し、通常画面の更新／再読み込みボタンが存在しないことを確認した。
- 同画面で Cmd+R キーボードイベントが `defaultPrevented: true` となり、画面再取得へ渡ることを確認した。

## 残タスク

- PR CIで未変更領域を含む統合チェックを確認する。
- マージ後のCloud Appデプロイと公開画面確認は別途実施する。
