# キャディ配置画面のタブ分離 設計

## Context

`DispatchView` は現在、日付選択の下に未配置の予約、自動配置、別業務、配置済み一覧、
需給・コース別過不足・推薦を順番に描画している。これらは同じ日付を参照するが、利用者の
目的は異なる。予約へキャディを付ける作業と、ラウンド以外の業務を記録する作業を同じ列に
置くと、作業開始点と完了状態が見えにくい。

設計の正本は、日付と共通件数を維持しながら、作業単位だけをタブで分離することである。
データ契約や既存の認可境界は変更しない。

## Goals / Non-goals

### Goals

- 最初に「何の作業をする画面か」をタブで選べる。
- タブの切り替え後も対象日と運用状況を失わない。
- 予約配置の主作業を上から順に追え、判断材料は必要時だけ開ける。
- 別業務の登録・解除をラウンド配置から視覚的に分離する。
- 空状態と件数の意味を、操作可能な次の行動と一緒に明示する。

### Non-goals

- 新規のAPI、DBテーブル、Field連携、authz action、migration。
- 自動配置アルゴリズム、候補順位、別業務の時間重複ルール、需給計算の変更。
- 別業務データの永続化場所の変更。

## Options considered

### A. 既存の縦並びを維持し、見出しだけ整える

変更量は小さいが、予約配置と別業務の目的が同じページの同じ流れに残る。スクロール量も減らず、
利用者が作業モードを切り替えたことを認識しにくいため採用しない。

### B. 「ラウンド配置」「別業務」の2タブに分ける（採用）

操作目的を明確に分けつつ、日付と件数を共通表示できる。既存の
`UnassignedRoundsPanel`、`AutoAssignPanel`、`CaddieDutiesPanel`、配置済み一覧を大きく
作り直さずに表示境界を整理できる。

### C. 自動配置・判断材料もそれぞれタブにする

自動配置は手動配置と同じ「予約へキャディを付ける」手段であり、判断材料は主作業を補助する情報で
ある。タブを増やすと作業の順序と状態が分断されるため採用しない。

## Proposed information architecture

```text
キャディの配置
┌────────────────────────────────────────────────────────┐
│ [ラウンド配置] [別業務]                                  │  ← 最上段の操作要素
├ 日付 2026-09-01 │ 未配置 3組 │ 配置済み 12組 │ 別業務 2人 │ 空き 4人 ┤
│                                                        │
│ ラウンド配置                                           │
│   未配置を解消する                                     │
│   ┌ 未配置の予約 ─────┬ 自動配置 ─────────┐             │
│   │ 期間、絞り込み、決定 │ 試す → この配置で決める │             │
│   └───────────────────┴───────────────────┘             │
│   配置済み 12組（折りたたみ）                          │
│     配置行、付け替え                                   │
│   判断材料（折りたたみ）                               │
│     需給、コース別過不足、おすすめ候補                  │
│                                                        │
│ 別業務                                                 │
│   既存の CaddieDutiesPanel                             │
│     別業務中のキャディ、空き時間のあるキャディ、登録/解除 │
└────────────────────────────────────────────────────────┘
```

### タブ

- 初期タブは `rounds`（表示文言は「ラウンド配置」）。未配置件数が確定している場合は、色だけに
  頼らないテキストの件数バッジを付ける。
- 2つ目は `duties`（表示文言は「別業務」）。別業務中の人数を補助情報として表示してよいが、
  件数が未取得のときに0と断定しない。
- タブの順序は固定し、タブの上に日付や大きな説明パネルを置かない。ページ見出しがある場合も、
  タブはこの画面の最初の操作要素とする。

### 共通サマリー

タブの直下に1行で置く。日付pickerと、次の状態を同じ日付文脈で表示する。

| 項目 | 意味 | 未取得時 |
|---|---|---|
| 日付 | 両タブが扱う選択日 | 既存のdate loading/初期値ルールに従う |
| 未配置 | 選択日のキャディ付き予約のうち担当未決定の組数 | 数値を隠すか「確認中」 |
| 配置済み | 選択日の担当決定済みの組数 | 数値を隠すか「確認中」 |
| 別業務中 | 選択日に別業務が登録されているキャディ数 | 数値を隠すか「確認中」 |
| 空き | 既存の別業務/ラウンド条件から見た空き時間のあるキャディ数 | 数値を隠すか「確認中」 |

サマリーは既存resourceのデータを組み合わせて導出し、新しい集計endpointを作らない。登録・解除・
配置・付け替えの成功後は、既存のrefresh経路で一覧とサマリーを同時に更新する。

### ラウンド配置タブ

表示順を作業の流れに合わせる。

1. 「未配置を解消する」を主作業として見出し化し、広い画面では `UnassignedRoundsPanel` と
   `AutoAssignPanel` を主従の2列に置く。狭い画面では同じ順序で1列に戻す。
2. `UnassignedRoundsPanel` — 未配置の予約。期間（この日/7日/14日）とコース絞り込みをこの中に置く。
3. `AutoAssignPanel` — 自動配置の試行、プレビュー、確定。未配置0件では実行ボタンを無効化し、
   「配置する予約がありません」など理由を近くに表示する。
4. 配置済み一覧 — 件数を表題に含む折りたたみへ移し、初期状態では閉じる。当日の配置、取消・
   異常表示、付け替えの既存操作は中に維持する。
5. 判断材料 — `DailySupplyPanel`、`CourseBalancePanel`、`RecommendationsPanel` を
   `CollapsibleSection` 配下に置く。閉じた状態では主作業を押し下げない。

期間表示の予約一覧と共通サマリーの対象日は異なる。サマリー・配置済み一覧・別業務は選択日のみ、
未配置一覧だけが選択日からの7日/14日へ広がることを明示する。

### 別業務タブ

`CaddieDutiesPanel` をこのタブだけに表示する。説明は1文に抑え、空き時間のある人数は登録ボタンの
横に置く。既存の別業務中のキャディ行、業務種別・時間帯・メモ・解除の動作を維持する。タブ内にラウンド
一覧や自動配置を複製しない。登録・解除後は共通サマリーとラウンド配置の候補が再取得される。

## URL and state

画面状態を次のqueryで表す。

```text
/<tenant>/golf/caddies/dispatch?date=2026-09-01&tab=rounds
/<tenant>/golf/caddies/dispatch?date=2026-09-01&tab=duties
```

- 既存の `date` の正規化・fallbackを再利用する。
- `tab` は `rounds` / `duties` だけを受け、欠落・不正値は `rounds` とする。
- タブ切り替えと日付変更で、もう一方のqueryを消さない。
- 再読み込み、リンク共有、ブラウザの戻る/進む、サイドバーからの遷移で状態が不意に今日や別タブへ
  戻らないことを確認する。
- 既存のルーターのURL更新方式に合わせ、タブ・日付の変更が未保存フォームのガードを迂回しない。

## Accessibility

- タブ本体は `role="tablist"`、各タブは `role="tab"` とし、`aria-selected`、`aria-controls`、
  `tabIndex` を正しく設定する。
- パネルは `role="tabpanel"`、対応する `id` と `aria-labelledby` を持つ。非表示パネルは支援技術から
 も非表示にする。
- 左右矢印でタブ間を移動し、Enter/Spaceで選択できる。2タブなので端で循環するか、Home/Endを
  含む挙動をテストで固定する。
- 未配置件数などはバッジの色だけで示さず、ラベルと数値を読み上げ可能なテキストで出す。
- 日付picker、期間切り替え、折りたたみ、登録・解除・付け替えボタンに可視ラベルを付ける。
- 空状態は「0件」とだけ出さず、何が無いのかと、必要なら次の行動を説明する。
- 保存・解除後は通知だけでなく該当行と共通サマリーを更新する。失敗時は操作付近に再試行可能な
  エラーを残す。

## Data, API, and authorization boundary

画面の表示条件だけを変更し、既存の読み書き契約を使う。`/v1/course` 配下の既存endpoint、
Fieldへのbearer転送、`src/course_authz.rs` のroute分類、CourseBoardローカルDBのモデルは
変更しない。新規のAPI/DB/authzが必要と判明した場合は本設計を拡張せず、別タスクとして切り出す。

## Empty and loading states

| 状態 | 表示 |
|---|---|
| キャディ付き予約が0件 | 「この日のキャディ付き予約はありません」 |
| 予約はあるが全件配置済み | 「すべての組にキャディが決まっています」 |
| 7日/14日の期間内に未配置なし | 「この期間に未配置の組はありません」 |
| 別業務が0件 | 「この日の別業務はありません」＋空き時間のあるキャディを次の行動として表示 |
| loading/error | 既存の `LoadingState` / `ResourceError`。未取得を成功の0件として扱わない |

## Test and rollout plan

### Local

- タブ初期値、不正値fallback、URLへのdate/tab保持、日付変更後のtab保持をテストする。
- ラウンド配置で4ブロックの表示順と別業務非表示、別業務で `CaddieDutiesPanel` のみ表示されることを
  テストする。
- 予約0件、全件配置済み、7日/14日空、別業務0件の文言をテストする。
- タブのARIA属性、左右キー操作、選択パネルとの対応をテストする。
- 既存の未配置手動配置、自動配置preview/確定、別業務登録/解除、配置済み付け替えテストを回帰させる。
- `npm run type-check`、`npm run test`、`npm run build`、`git diff --check` を実行する。

### Preview

- Ready PRからPreviewへデプロイされたbuild/URLを特定する。
- 認証済みoperatorで対象tenantを選び、`/golf/caddies/dispatch` を開く。
- デスクトップ幅と狭い幅で、タブが最上段、サマリーが直下、各タブの表示範囲が保たれることを確認する。
- URLを直接開く、再読み込み、タブ切り替え、日付変更、戻る/進むで状態を確認する。
- 実データの予約0件/配置済み/未配置、別業務登録・解除、候補更新を確認する。実データを作る場合は
  明示的なテスト対象に限定し、終了後に後始末する。
- Previewの画面証拠は、ローカル/mock、Preview API、認証済みブラウザの各ゲートを分けて記録する。

## Open questions / deferred

- タブ切り替えをブラウザ履歴の1エントリにするかは、既存routerのquery更新方針とUX確認で決める。
  どちらを採ってもURLの再現性は必須とする。
- 未配置件数と空き人数のresourceが異なる状態で一部失敗した場合の表示文言は、実装時に既存
  `ResourceError` の表現と揃える。0件へのfallbackは行わない。
- コース別過不足などの判断材料を将来独立画面にする必要が出た場合は、別のUI/情報設計タスクで扱う。

## ADR decision

ADRは作成しない。既存のCourseBoard責務・API・認可を変更せず、単一画面内の表示ワークフローを
整理するため、長期的なアーキテクチャ判断には該当しない。
