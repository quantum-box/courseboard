# キャディ配置画面のタブ分離と情報設計

## 目的

`/golf/caddies/dispatch` の画面を、目的の違う「ラウンド配置」と「別業務」に分ける。
タブを画面上部に置き、その直下に日付と件数だけのコンパクトな共通サマリーを表示する。
ラウンド配置では予約へキャディを割り当てる作業に集中し、別業務ではラウンド以外の業務を
記録・解除できる構成にする。

## 背景

現在の `DispatchView` は、未配置の予約、自動配置、別業務、配置済みの一覧、需給などの
判断材料を同じ縦列に並べている。異なる目的の操作が混ざるため、利用者が「予約に人を付ける」
のか「別業務を登録する」のかを画面構造から判断しにくく、情報量の多い日には主作業が下へ
押し出される。

別業務そのものの記録モデルと操作は、既存の [キャディの別業務割り当て](../../../in-progress/caddie-alternative-duty/task.md)
で定義されたものを利用する。本件はその画面上の分類と導線を整理する作業であり、別業務の
業務ルールを再定義しない。

## スコープ

- `ラウンド配置` / `別業務` の2タブを追加し、タブを画面内の最上段の操作要素に置く。
- タブ直下に、日付、未配置、配置済み、別業務中、空きキャディの共通サマリーを1行で置く。
- `ラウンド配置` 内を、未配置の予約、自動配置、この日の配置済み、折りたたみ可能な判断材料の
  順に整理する。
- `別業務` 内を、既存の `CaddieDutiesPanel` による別業務一覧と空き時間のあるキャディの導線に
  絞る。
- `date` と `tab=rounds|duties` をURLに保持し、再読み込み・共有・戻る/進む操作で同じ表示状態を
  復元できるようにする。`tab` が無い、または不正な場合は `rounds` を初期値とする。
- 予約0件、全件配置済み、期間内に未配置なし、別業務0件を区別して表示する。
- タブのARIA、キーボード操作、フォーカス、件数のテキスト表示を実装し、色だけに依存しない。
- 実装後にローカルテストとPreview環境で、両タブ・URL状態・空状態・主要操作を確認する。

## 非スコープ

- Field API、CourseBoard API、DBスキーマ、migration、認証・認可、`src/course_authz.rs` の変更。
- 予約割り当て、別業務、需給計算、自動配置、付け替えの業務ルールやHTTP契約の変更。
- 新しいタブ（自動配置や判断材料など）の追加。
- 別業務マスタや設定画面の作り替え。
- Linear issue の作成（本件はユーザー直依頼）。

## 対象ファイル・モジュール

- `desktop/src/features/golf/CaddiesPage.tsx` — `DispatchView` のタブ状態、共通サマリー、表示順。
- `desktop/src/features/golf/UnassignedRounds.tsx` — 未配置一覧、期間切り替え、空状態。
- `desktop/src/features/golf/CaddieDutyBoard.tsx` — 別業務タブ内の既存パネル配置。
- `desktop/src/features/golf/{CaddiesPage,CaddieDutyBoard,UnassignedRounds}*.test.*` — UI状態・操作の回帰テスト。
- `desktop/src/i18n/locales/{ja,ja-plain,en}/caddies.ts` — タブ、サマリー、空状態、ARIA関連の文言。
- 必要な場合のみ `desktop/src/styles.css` または既存のUI部品 — レイアウトとフォーカス表示。

実装では既存の `caddie-assignments`、`tee-sheet`、`caddie-recommendations`、
`caddie-duty-assignments`、`caddie-shifts` 等の取得結果を再利用し、新規endpointを追加しない。

## 実装フェーズ

1. URLの `tab` 状態を追加し、既存の `date` を失わずにタブを切り替えられるようにする。
2. タブを最上段へ置き、日付・件数の共通サマリーを直下へ移す。
3. ラウンド配置と別業務のパネルを各タブへ移し、ラウンド側の順序と判断材料の折りたたみを整える。
4. 空状態、無効状態、保存後の一覧・件数更新、タブのARIAとキーボード操作を整える。
5. desktopのテスト・type-check・buildを実行し、Preview環境で認証済みブラウザ確認を行う。

## 完了条件

- 画面を開いたとき、最初にラウンド配置/別業務のタブが見え、タブ直下に共通サマリーがある。
- ラウンド配置には未配置、自動配置、配置済み、判断材料だけが表示され、別業務パネルは表示されない。
- 別業務には別業務パネルが表示され、ラウンド一覧・自動配置・需給判断材料は表示されない。
- `date` と `tab` を含むURLを再読み込み・共有して、同じ日付とタブが開く。不正な `tab` は安全に
  ラウンド配置へ戻る。
- 予約0件と全件配置済みを別の文言で示し、7日/14日表示の空状態も表示範囲と一致する。
- タブをキーボードで移動・選択でき、選択中タブと対応パネルが支援技術へ正しく伝わる。
- 既存の予約割り当て・別業務登録/解除・自動配置・付け替えのAPI呼び出しと動作を壊していない。
- ローカル検証とPreview検証の結果を [検証レポート](verification-report.md) に記録する。

## リスクとフォローアップ

- 共通サマリーの件数が複数resourceのロード状態に依存するため、未取得を0件と誤表示しない。
  loading/error時は既存の状態表示ルールに従い、確定していない数値を断定しない。
- タブ分離後も別業務の登録・解除がラウンド側の候補と件数へ反映される必要がある。変更後に
  既存refresh経路を通して両タブの表示を更新する。
- Previewで実データ・権限・Field接続が不足している場合は、ローカル/mock確認と分けて未確認の
  ゲートとして記録する。別途API/DB/authz変更が必要になった場合は本タスクの範囲外として起票する。
