# キャンセル料の表示状態と入金操作の設計

## 問題

Field invoice の保存済み `status` と、CourseBoard の業務画面で必要な表示状態は
完全には一致しない。未入金の `Sent` / `SendFailed` / `Draft` が支払期限を過ぎても、
Field が `Overdue` へ遷移させなければ現在の画面は延滞として扱わない。

一方、`Paid` は単なる表示状態ではなく入金の事実である。通常の `PATCH /v1/invoices/:id`
から選べる状態にすると、Stripe 決済、現金入金、誤操作を区別できない。

## 方針

### 表示状態

CourseBoard は次の場合だけ表示上の状態を `Overdue` とする。

- 保存済み状態が `Paid` でも `Overdue` でもない
- `dueDate` がテナント timezone の今日より前である

`Paid` は期限に関係なく `Paid` を維持する。期限当日は期限超過にしない。
不正な `dueDate` は保存済み状態へフォールバックし、画面全体を落とさない。

一覧は Field へ保存済み status の絞り込みを渡さず、取得した請求へ表示状態を適用してから
クライアント側で絞り込む。これにより、保存済み `Sent` だが業務上 `Overdue` の行を
「期限すぎ」に含められる。ただし Field 一覧のページング対応は PLT-4118 で別途扱う。

### 入金状態

通常の状態変更で選べるのは `Draft`、`Sent`、`SendFailed`、`Overdue` に限定する。
既に `Paid` の請求は状態選択と更新を無効にする。

現金などの手動入金は、理由、操作者、日時、金額、証憑を持つ Field の汎用 contract が
必要である。このタスクでは、監査情報のない `Paid` 更新を代替手段として残さない。

## 代替案

Field が期限到来時に全 invoice を `Overdue` へ永続更新する案は、通知や督促の正本としては
望ましい。ただしスケジューラ、timezone、再実行、監査の設計が必要であり、CourseBoard の
表示不具合を直す範囲を超える。Field 側の決済・照合 contract は PLT-4117 / PLT-4118 で扱う。

## セキュリティと会計

- `Paid` をUIから隠すだけでは Field API の直接操作を禁止できない。Field 側で状態遷移を
  制約することが最終防壁である。
- CourseBoard は Field invoice を正本とし、独自の入金テーブルを追加しない。
- 期限超過は表示上の派生値であり、Field の保存済み status を自動更新しない。

## テスト

- 期限前、期限当日、期限後
- `Paid` と保存済み `Overdue`
- 不正な `dueDate`
- 「期限すぎ」絞り込みと集計
- 通常状態の選択肢に `Paid` が無いこと
- 既に `Paid` の請求で更新操作が無効なこと
